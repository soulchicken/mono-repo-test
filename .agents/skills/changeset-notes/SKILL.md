# Changeset Notes

feature → develop PR에 포함할 `.changeset/*.md`를 작성한다. 노트는 이후 패키지 CHANGELOG와 GitHub Release 본문으로 사용되므로, 실제 코드에서 확인한 사용자 관점의 변경을 한국어로 설명한다.

## 변경 범위 확인

- 이 스킬을 포함한 저장소 루트에서 작업한다. 상위 저장소나 다른 저장소의 변경을 섞지 않는다.
- `git status --short`, `.changeset/config.json`, `pnpm-workspace.yaml`, 해당 패키지의 `package.json`과 기존 `.changeset/*.md`를 읽는다.
- 사용자가 지정한 파일·커밋·PR 범위를 우선한다. 별도 지정이 없으면 설정의 `baseBranch`인 develop을 기준으로 feature 브랜치의 변경을 읽는다. 로컬에 존재하는 `origin/develop` 또는 `develop`으로 merge-base를 구해 `git diff <merge-base> HEAD`를 확인하고, staged·unstaged diff 및 관련 untracked 소스도 읽는다.
- develop 자체에서 작업 중이면 작업 트리 변경을 기본 범위로 한다. 비교 기준이 없으면 임의로 main이나 전체 이력을 대신 사용하지 말고 필요한 기준만 확인한다.
- 커밋 제목만으로 내용을 추측하지 말고 변경 코드와 관련 호출부·테스트를 읽는다. 동작을 유지하는 리팩터링, 테스트, 문서, 스킬, CI만 바뀌었다면 changeset을 생략하고 이유를 알린다. 의존성·빌드·설정 변경은 실제 패키지 동작이나 산출물에 영향이 있는지 판단한다.

## 패키지와 증가 종류

현재 패키지 구성이며, 실제 이름과 경로는 manifest로 다시 확인한다.

| 경로              | 패키지           | 역할             |
| ----------------- | ---------------- | ---------------- |
| `packages/ui`     | `@sample/ui`     | 공유 버튼 API    |
| `apps/web`        | `@sample/web`    | UI를 사용하는 앱 |
| `packages/config` | `@sample/config` | 공유 테스트 설정 |

- patch: 기존 동작의 오류 수정. 예: null variant의 기본값 처리.
- minor: 기존 호출과 호환되는 기능·옵션 추가. 예: 선택 가능한 버튼 variant 추가.
- major: 기존 호출이나 계약을 깨뜨리는 변경. 제거·이름 변경·필수 인자 추가 등이 해당하며, 필요한 전환 방법도 노트에 쓴다. 현재 버전이 0.x라는 이유로 종류를 임의로 낮추지 않는다.
- 사용자 지정 종류가 코드와 충돌하면 근거를 설명하고 충돌하는 선택만 확인한다. 코드로 판단 가능한 일반적인 수정은 종류를 선택해 바로 작성한다.
- 직접 릴리스할 변경이 있는 패키지만 frontmatter에 적는다. UI에 의존한다는 이유만으로 web을 추가하지 않는다. 역의존성 버전 전파는 Changesets에 맡기고 `status` 결과로 확인한다. config만 바뀐 경우에도 개발 의존 패키지를 일괄 추가하지 않는다.
- `private: true`인 패키지도 이 저장소 설정에서는 버전 관리 대상이다. 저장소 루트 패키지는 대상에서 제외한다.

## 노트 작성

한 변경을 이미 설명하는 미소비 changeset이 있으면 중복 생성하지 않는다. 다른 작업의 파일은 유지한다. 같은 패키지라는 이유만으로 기존 노트에 합치지 말고, 현재 작업에 속한 노트를 보완하거나 새로운 변경 단위의 파일을 만든다. 기존 증가 종류를 근거 없이 낮추지 않는다.

`.changeset/<변경을-설명하는-영문-kebab-case>.md`를 직접 작성할 수 있다. 기존 파일명을 덮어쓰지 않는다. 명시적으로 초안만 요청한 경우에는 파일을 쓰지 않고 내용을 제시한다.

```md
---
'@sample/ui': patch
---

버튼 variant에 null을 전달하면 기본 primary 값을 사용하도록 수정했습니다.
```

무엇이 추가·수정됐는지와 사용자에게 미치는 영향을 간결하게 쓴다. 함수·옵션 이름은 정확히 적고, 확인하지 않은 원인·성능·호환성·이슈 번호를 만들지 않는다. 서로 다른 패키지의 관련 변경은 하나의 파일에 함께 적을 수 있으며, 본문에서 각 변경을 구분한다.

## 검증과 마무리

저장소의 `packageManager`에 맞는 pnpm으로 `pnpm changeset status`를 실행해 파일 파싱과 예상 버전 전파를 확인한다. pnpm 버전이 다르면 사용 가능한 지정 버전 실행기를 사용한다. 실행 환경 문제로 검증하지 못했다면 검증 완료라고 보고하지 않는다.

새로 작성·수정한 노트의 경로, 대상 패키지와 증가 종류, 선택 근거, status 결과를 짧게 알린다. 기존 미소비 changeset이 함께 계산된 경우 이번 노트의 대상과 전체 예정 릴리스를 구분한다. 재실행 시 동일 노트를 추가하지 않는다.

이 작업에서는 package.json 버전이나 CHANGELOG를 직접 올리지 않고 `pnpm version-packages`도 실행하지 않는다. 버전 PR이 그 작업을 맡는다. 스킬 호출만으로 커밋·push·PR 생성·병합·태그·Release 게시를 수행하지 않는다. 해당 작업은 사용자가 요청한 범위에 있을 때만 이어서 진행한다.
